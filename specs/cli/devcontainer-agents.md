# Devcontainer Agent Isolation Specification

## Purpose

Sandboxed execution environment for AI agents using VS Code devcontainers. Provides filesystem isolation so agents can safely run with `--dangerously-skip-permissions` without access to the host machine beyond their mounted worktrees.

## Core Concepts

- **Devcontainer**: Docker-based development environment defined by `.devcontainer/devcontainer.json`
- **Filesystem Isolation**: Agent can only access explicitly mounted directories
- **Safe Autonomous Execution**: `--dangerously-skip-permissions` is safe because damage is limited to worktrees
- **Per-Agent Configuration**: Each agent can have customized container settings

## Security Model

### What Agents CAN Access
- Mounted worktree directories (`/workspaces/`)
- Network (for Claude API, npm, git remotes)
- Tools installed in container (node, git, etc.)

### What Agents CANNOT Access
- Host filesystem (`~/.ssh`, `~/.aws`, other projects)
- Host processes
- System files
- Browser data, credentials, passwords

### Devcontainer Creation Locations

Devcontainers are automatically created in these locations:

1. **Agent worktrees** (`prlt agents add`): Each agent gets a `.devcontainer/` for sandboxed execution
2. **Central repos** (`prlt repos add`): Each repo in `repos/` gets a `.devcontainer/`
3. **Separate PMO** (`prlt pmo init --location separate`): The PMO repo gets a `.devcontainer/`

## Devcontainer Generation

### Default Behavior

When adding agents, devcontainer config is generated by default:

```bash
prlt agents add altman              # Creates .devcontainer/ by default
prlt agents add altman --container  # Explicit (same as above)
prlt agents add altman --no-container  # Skip devcontainer setup
```

### Generated Structure

```
agents/staff/altman/
├── .devcontainer/
│   ├── devcontainer.json
│   └── Dockerfile (optional)
├── .proletariat/
│   └── config.json
├── frontend/     (git worktree)
└── backend/      (git worktree)
```

### Default devcontainer.json

```json
{
  "name": "Agent: altman",
  "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
  "features": {
    "ghcr.io/devcontainers/features/node:1": {},
    "ghcr.io/devcontainers/features/git:1": {}
  },
  "customizations": {
    "vscode": {
      "extensions": []
    }
  },
  "postCreateCommand": "npm install -g @anthropic-ai/claude-code",
  "workspaceFolder": "/workspaces",
  "runArgs": [
    "--memory=8g",
    "--cpus=4"
  ],
  "mounts": []
}
```

Note: The workspace folder points to `/workspaces` which will contain all mounted repo worktrees.

### Multi-Repo Mount Configuration

For agents with multiple repository worktrees:

```json
{
  "name": "Agent: altman",
  "workspaceFolder": "/workspaces",
  "mounts": [
    "source=${localWorkspaceFolder}/frontend,target=/workspaces/frontend,type=bind",
    "source=${localWorkspaceFolder}/backend,target=/workspaces/backend,type=bind"
  ]
}
```

## Automatic Devcontainer Usage

### How It Works

When executing a ticket, if the agent has a `.devcontainer/` directory, **devcontainer is always used automatically**. The user only chooses how to display the output:

```
? How should the agent output be displayed?
  terminal     - New terminal window (macOS)
  foreground   - Run in current terminal
  tmux         - New tmux pane/window
  background   - Detached process, logs to file
```

This ensures agents always run sandboxed when a devcontainer config exists.

### Execution Flow

1. Check if agent has `.devcontainer/devcontainer.json`
2. If yes:
   - Always use devcontainer (sandboxed)
   - Prompt for display mode (terminal, foreground, background, tmux)
   - Show: `🐳 Sandboxed: devcontainer (display: terminal)`
3. If no:
   - Fall back to legacy mode selection
   - Show warning: `⚠️ Mode: terminal (no sandbox - running on host)`

### Command Examples

```bash
prlt ticket execute TKT-001                      # Auto-detect, prompt for display
prlt ticket execute TKT-001 --mode terminal      # Devcontainer + new terminal window
prlt ticket execute TKT-001 --mode foreground    # Devcontainer + current terminal
prlt ticket execute TKT-001 --mode background    # Devcontainer + log to file
```

### No Devcontainer Fallback

If the agent doesn't have a devcontainer, the legacy mode selection is shown with a warning:

```
? Select execution mode (no devcontainer - running on host):
  terminal     - New terminal window (macOS)
  foreground   - Run in current terminal
  ...
```

## Devcontainer Runner Implementation

### runDevcontainer Function

```typescript
export async function runDevcontainer(
  context: ExecutionContext,
  executor: ExecutorType,
  config: ExecutionConfig
): Promise<RunnerResult> {
  const devcontainerPath = path.join(context.worktreePath, '.devcontainer');

  // Check devcontainer CLI is installed
  try {
    execSync('which devcontainer', { stdio: 'pipe' });
  } catch {
    return {
      success: false,
      error: 'devcontainer CLI not found. Install with: npm install -g @devcontainers/cli'
    };
  }

  // Start or reuse container
  try {
    execSync(`devcontainer up --workspace-folder "${context.worktreePath}"`, {
      stdio: 'pipe'
    });
  } catch (error) {
    return {
      success: false,
      error: `Failed to start devcontainer: ${error}`
    };
  }

  // Build command
  const prompt = buildPrompt(context);
  const { cmd, args } = getExecutorCommand(executor, prompt, true);
  const fullCmd = [cmd, ...args].map(a => `'${a.replace(/'/g, "'\\''")}'`).join(' ');

  // Execute inside container
  try {
    execSync(
      `devcontainer exec --workspace-folder "${context.worktreePath}" ${fullCmd}`,
      { stdio: 'inherit' }
    );

    return {
      success: true,
      containerId: `devcontainer-${context.agentName}`,
    };
  } catch (error) {
    return {
      success: false,
      error: `Execution failed: ${error}`
    };
  }
}
```

## Container Lifecycle Commands

### `prlt agent container start [name]`

**Purpose**: Start an agent's devcontainer

**Arguments**:
- `name` (optional): Agent name. Prompts if not provided.

**Behavior**:
```bash
devcontainer up --workspace-folder /path/to/agents/staff/altman
```

**Output**:
```
🐳 Starting container for agent: altman
   Image: mcr.microsoft.com/devcontainers/base:ubuntu
   Workspace: /workspaces

✓ Container started
  Container ID: abc123...
```

---

### `prlt agent container stop [name]`

**Purpose**: Stop an agent's running devcontainer

**Arguments**:
- `name` (optional): Agent name. Prompts if not provided.

**Options**:
- `--force, -f`: Force stop without graceful shutdown

**Output**:
```
🛑 Stopping container for agent: altman

✓ Container stopped
```

---

### `prlt agent container rebuild [name]`

**Purpose**: Rebuild agent's devcontainer (after config changes)

**Arguments**:
- `name` (optional): Agent name. Prompts if not provided.

**Options**:
- `--no-cache`: Rebuild without using cached layers

**Output**:
```
🔄 Rebuilding container for agent: altman
   Stopping existing container...
   Building new image...
   Starting container...

✓ Container rebuilt successfully
```

---

- `name` (optional): Agent name. Shows all if not provided.

## Configuration

### Global Defaults

```bash
# Default to using devcontainers for new agents
prlt config set agents.default_container true

# Default container image
prlt config set devcontainer.default_image mcr.microsoft.com/devcontainers/base:ubuntu

# Default resource limits
prlt config set devcontainer.memory 8g
prlt config set devcontainer.cpus 4
```

### Per-Agent Customization

Users can edit `.devcontainer/devcontainer.json` directly to:
- Change base image
- Add features (Python, Rust, Go, etc.)
- Adjust resource limits
- Add VS Code extensions
- Configure environment variables

## Integration with Execute Command

### Updated Execute Flow

1. **Check for devcontainer**
   ```typescript
   const devcontainerConfig = path.join(agentDir, '.devcontainer', 'devcontainer.json');
   const hasDevcontainer = fs.existsSync(devcontainerConfig);
   ```

2. **Mode Selection** (if not specified)
   - If devcontainer exists: default to `devcontainer` mode
   - If no devcontainer: show standard mode selection

3. **Container Startup**
   - Check if container is running
   - Start if needed (`devcontainer up`)
   - Wait for ready state

4. **Execute**
   - Run Claude inside container via `devcontainer exec`
   - Pass prompt and flags

5. **Track Execution**
   - Store container ID in execution record
   - Monitor for completion

## Types

### Updated RuntimeMode

```typescript
export type RuntimeMode =
  | 'devcontainer'  // Sandboxed devcontainer (recommended)
  | 'foreground'    // Subprocess in current terminal
  | 'background'    // Detached process, logs to file
  | 'tmux'          // New tmux pane/window
  | 'terminal'      // New Terminal.app window (macOS)
  | 'docker'        // Raw Docker container
  | 'vm'            // Remote VM via SSH
```
